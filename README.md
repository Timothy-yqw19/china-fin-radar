# 金融政策雷达 · 秋招知识库（finradar）

面向 **券商 / 公募基金 / 银行秋招** 的一体化工具：一边**抓政策为主导的金融新闻**，
一边把这些政策**接回考点**——每个热词都配好定义、出处、考点清单、
60–90 秒口语化答法和追问应对。

```
新闻抓取 ──▶ 政策打分与标签 ──▶ 热词榜 / 日报
                                   │
                                   └──▶ 热词库（含考点+答法）──▶ 刷题与错题本
```

---

## 它解决什么问题

秋招准备最常见的三种低效：

| 症状 | 这个项目怎么处理 |
|---|---|
| 每天刷一堆财经快讯，记不住也用不上 | 给每条新闻打**政策相关度分**（0–100），只精读 ≥60 分的；每条自动附一句**传导逻辑**（"所以呢"） |
| 知道"五篇大文章""中长期资金入市"这些词，但一被追问就露怯 | 每个词条含**考点清单 + 面试口语化答法 + 追问及应答**，不是词典释义 |
| 背了一堆，面试时组织不出语言 | 所有答案都写成**能直接说出口的口语**，控制在 60–90 秒 |
| 想在面试里说清"这几年金融政策有什么变化"，却没有时间线 | `finradar backfill` 回捞 2021 年以来**政策文件**，`hot --window 5y --trend` 给出**词 × 年演变矩阵**（哪个词哪年出现、哪年升温、被谁替代） |
| 只看到一条条新闻，串不成"这条路怎么走到今天、接下来会怎样" | **专题报道 + 专题洞察**：每条主线给足脉络（人工 + 从库里自动聚合）+ 现状快照 + **各主体（监管/公募/券商/银行/保险/外资）可能的动作（带触发条件）** + 该盯哪些信号；做成网页版可手机翻（报道是成篇文章，洞察是条目速查） |
| 名词记不住、也不知道哪些词值得背 | **名词档案**：46 个热词全部自动生成档案（定义/考点/答法 + 语料里出现多少次、首见哪一年、代表文件），另有**候选新词**从过去几年的政策文件里挖出来待你确认 |

## 快速开始

```bash
git clone https://github.com/Timothy-yqw19/china-fin-radar.git
cd china-fin-radar
pip install -r requirements.txt
pip install -e .            # 装好后可以直接用 finradar 命令

# 一条命令更新全部：第一次补齐过去十年，之后每次只抓上次运行到现在的新增
finradar update

# 先看看长什么样（不联网）
python scripts/demo_seed.py

# 数据源体检：哪个接口通、哪个要修
finradar doctor

# 抓官方政策站点 + 财经快讯
finradar crawl --source all --pages 1

# 生成政策日报（Markdown + 可直接打开的 HTML）
finradar report --days 3 --min-score 55

# 看长周期：回捞历史（一次性），然后按 3m/6m/1y/3y/5y 看
finradar backfill --from 2015-01-01        # 政策库可回溯到 2013 年，一次补到十年前
finradar hot --window 10y --trend          # 词 × 年 演变矩阵（起落一目了然）
finradar report --window 10y --min-score 70 # 十年政策回顾

# 近 30 天热词榜 + 新词发现
finradar hot --days 30 --discover

# 扩大词表：大众热榜（头条/抖音/百度）+ 批量挖掘候选提法
finradar crawl --source trends
finradar trends                          # 热榜里今天有哪些财经话题在火
finradar mine --top 200 --trends         # 从全部语料里挖候选提法
finradar mine --top 200 --out output/drafts/terms_draft.yaml

# 改了 config/keywords.yaml 之后，不用重抓，直接把库里已有条目重算一遍
finradar rescore

# 查一个词的完整解析
finradar term QDII

# 专题报道：成篇的文章（导语 + 脉络 + 各方动作 + 反方观点）
finradar features                           # 6 篇报道的标题与导语
finradar feature QDII                       # 读一篇
finradar features --out output/features.md  # 全部合并导出成 Markdown
finradar feature QDII --html                # 导出成网页

# 专题洞察（条目式速查）：这条线怎么走到今天、各方接下来可能做什么
finradar insights
finradar insight QDII
finradar report --window 1y --insights      # 报告末尾附上相关专题

# 网页版：专题洞察 + 46 条名词档案 + 候选新词（单文件，手机可看）
python scripts/build_insight_site.py        # → output/insights.html
finradar insight QDII --html                # 单条专题导成一个网页

# 刷题（10 题，随机；只刷错题加 --wrong）
finradar quiz -n 10
finradar quiz --board 宏观 --institution 券商
finradar quiz --wrong

# 拉最新宏观数据（LPR / M2 / CPI / 国债收益率，需 akshare）
finradar facts --keys lpr money_supply cpi
```

> 提示：抓取模块依赖能访问境内财经与政务站点的网络环境。
> 在受限网络（如部分云环境）下会全部超时，属正常现象——先用
> `python scripts/demo_seed.py` 看输出效果。

## 数据源

| 类型 | 数据源 | 通道 | 备注 |
|---|---|---|---|
| 官方政策 | 中国政府网·政策文件库 | JSON | 各部委正式发文的统一收口，带文号和发文机关，最稳 |
| 官方政策 | 中国证监会 | JSON | 要闻 / 政策解读 |
| 官方政策 | 国家金融监督管理总局 | JSON | 政策法规 / 新闻发布 / 行政处罚 |
| 官方政策 | 中国人民银行 | HTML，失败自动回退政府网 | 新闻发布 / 法律法规 / 利率政策 / 公开市场业务交易公告 |
| 官方政策 | 国家外汇管理局 | HTML | 政策法规 / 外汇新闻 / 要闻发布，QDII 额度表在这里 |
| 官方政策（配置化） | 财政部 / 发改委 / 国家统计局 / 基金业协会 | HTML + `config/sources.yaml` | 加站点只填 selector，不用写代码 |
| 快讯 | 东方财富 7×24 / 财经早餐 | JSON | |
| 快讯 | 证券时报 | HTML + 配置化 | 实时快讯，补市场层面的新闻 |
| 大众热榜 | 今日头条 / 抖音 / 百度 | JSON | 看大众在关心什么；默认不参与政策统计（`--include-trends` 打开） |
| 快讯 | 财联社电报 | JSON（含 A/B 重点标记，自动提分） | |
| 快讯 | 同花顺 / 新浪 7×24 | JSON | |
| 兜底 + 宏观 | AkShare | Python 包 | 直连失败时的第二条腿；LPR/M2/CPI/社融等宏观数据的来源 |

以上 **15 个源在 2026-09-12 用 `finradar doctor` 在真实网络下逐个验证通过**，
一轮全量抓取约 1700 条。交易所（上交所 / 深交所）**没有接入**：它们的规则列表
是 JS 渲染的，HTML 骨架里没有数据，要抓得用 headless browser 或它们的内网 JSON 接口。

**历史数据**：政策文件库支持按日期范围回捞（`finradar backfill --from 2021-01-01`，
实测 2021—2026 每年 1000+ 份文件）；外汇局/统计局/发改委/基金业协会靠列表页翻页；
快讯类接口**只有当天**，所以 3 年以上的"热词演变"本质上是**政策提法**的演变。

**接口会变**。所以内置了 `finradar doctor` 逐源体检，并在
`config/sources.yaml` 里提供**配置化的 HTML 列表抓取器**——
加一个政务站点只需要填 selector，`require_date: true` 会自动滤掉导航菜单。

## 政策打分是怎么算的

规则写在 `config/keywords.yaml`，逻辑在 `finradar/analysis/tagger.py`：

1. **六类关键词各自加权**：政策动作（印发/施行/征求意见…）、发文主体（国务院/央行/证监会…）、
   货币政策、资本市场、银行保险、对外开放、主题热词。
2. **同类多次命中递减计分**，单类别封顶 2 倍权重 —— 防止堆砌关键词刷分。
3. **协同加分**：只有"官方主体 + 具体政策领域"同时命中才是真政策新闻
   （单独出现"央行"可能只是被引用，单独出现"降准"可能只是评论）。
4. **噪音与例行事项降权**：涨停、龙虎榜、概念股、午评这类直接扣分；
   领导会见、座谈、调研这类"有信息量但不是政策"的条目不扣重分、也不加分。
5. **附加传导逻辑**：命中特定词组时输出一句影响链，例如
   *化债 → 高息城投资产被低息政府债置换 → 银行资产质量改善但收益率下降 → 加剧"资产荒"*。

**来源先验分只做下限（0–30），不参与排序**：早期版本给官方站 70–80 分，
结果央行领导一场例行会见也能顶到 100 分，日报完全没有区分度。现在分数由关键词
信号决定：全库 1552 条里只有 28 条到 90 分以上（改口径前是 791 条），
例行会见、培训班这类事项落在 45–70 分。

```
[ 98.0] 中国人民银行         人民银行印发《中国人民银行"十五五"改革发展规划》
[ 97.5] 证监会            证监会就修订《上市公司重大资产重组管理办法》公开征求意见
[ 76.0] 政府网            国务院办公厅关于做好金融"五篇大文章"的指导意见
[ 62.0] 财联社            央行行长：继续实施适度宽松的货币政策，促进物价合理回升
[ 46.5] 政府网            关于推动中长期资金入市工作的实施方案
[  8.0] 快讯             午评：三大指数集体高开，AI概念股涨停，主力资金净流入
```

| 金融风险与监管体系 | 一行一局一会、穿透式监管、三大重点领域风险、存款保险、新《反洗钱法》、投资者保护、程序化交易监管 |

每个词条的字段：

```yaml
term: QDII（合格境内机构投资者）
heat: 5                    # 1-5，5 = 2026 秋招几乎必问
era / plan                 # 何时出现 / 属于哪个五年规划阶段
institutions: [公募, 银行, 券商]
source                     # 出处：哪份文件、哪次会议
definition / why_hot       # 是什么 / 为什么现在热
exam_points: [...]         # 考点清单（最容易被追问的点）
interview_answer           # 60-90 秒口语化答法，可直接背
facts_snapshot             # 关键数字 + 截止时点（会过期，标注 as_of）
followups: [{q, a}]        # 追问及应答
related: [...]             # 关联词
```

### 题库（`finradar/data/questions/`）

六大板块，每题含 **考点 / 标准答案 / 口语化表达 / 追问延伸**：

- 宏观与货币政策 · 固定收益与债券市场 · 权益投资与估值
- 公募基金与资产管理 · 银行与信贷 · 监管法规与职业素养（含行为面试）

题型包括单选、多选、简答和情景题（case）。刷题记录进 SQLite，
`finradar quiz --wrong` 只刷错题。

## 关于时效性

金融政策类内容会过期。项目用三种方式对冲：

1. **数字都标 `as_of`**（如 QDII 额度截至 2026-06-30 为 1761.69 亿美元），
   答题时说清截止时点比记错数字安全得多。
2. **`finradar facts`** 现拉 12 项宏观数据（LPR / M2 / CPI / PPI / GDP / PMI /
   SHIBOR / 社融 / 新增信贷 / 杠杆率 / 中美国债收益率 / 中债收益率曲线），
   不写死在文档里。各接口排序方向不一致（M2 是"新→旧"，LPR 是"旧→新"），
   所以内部统一按时间列重排后再取最新几期。
3. **`finradar hot --discover`** 做新词发现——把最近反复出现但词库里还没有的提法
   捞出来，人工确认后补进 `glossary/`。

日期一律按**北京时间**理解（境内站点的发布时间、快讯时间戳都是北京时间）；
在美东等时区跑，`近 N 天`的口径不会因为本机时区差一天。

> `--discover` 用的是字符 n-gram + 文档频率 + 左右邻多样性，**没有分词器**，
> 所以结果里会混进人名、机构名这类噪音，它是"提词器"不是词典，需要你人工过一遍。

## 开发

```bash
pip install -e ".[dev]"
pytest -q            # 185 passed
ruff check .
```

测试里有三组重要的守护：

- `test_basic.py` 逐条校验词库和题库的**字段完整性**（每个词必须有考点和口语化答法，
  每道选择题的正确项必须在选项里），防止后续补内容时写漏。
- `test_parsers.py` 用**离线样本**验证各站点的解析逻辑。接口若改版，
  这些测试会先失败，提示需要更新字段映射。
- 每个修过的真实 bug 都留了一条回归测试：政府网把结果挪进 `searchVO` 导致静默抓 0 条、
  央行列表把带 `index` 的详情链接全部过滤掉、`config/sources.yaml` 从没被 `build_all`
  加载过、宏观数据取成了 2008 年的、跨源重复条目没合并。
