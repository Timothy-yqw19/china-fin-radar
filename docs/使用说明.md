# 使用说明 · finradar

> 面向使用者的操作手册。想了解项目做了什么、哪些没做到，看 [项目总结.md](项目总结.md)。

---

## 0. 环境

`finradar` 已经装好了（在 `/opt/anaconda3/bin/finradar`），**在任何目录敲都可以**，
因为数据和日报都落在项目里的 `output/`，跟当前目录无关。

注意：系统自带的 `python3` 是 3.9，跑不动这个项目（需要 3.10+）。
要用 `finradar` 命令，或者显式用 `/opt/anaconda3/bin/python3`。

```bash
cd ~/Downloads/china-fin-radar     # 只有在改代码、跑测试、重新生成文档时才需要
finradar --version
```

换数据存放位置（比如试跑不想污染主库）：

```bash
FINRADAR_HOME=/tmp/finradar_test finradar crawl --source pbc
FINRADAR_HOME=/tmp/finradar_test finradar stats
```

## 0.5 一条命令更新全部（推荐）

不想记那么多命令就用这一条，它把"抓取 → 回捞 → 重算 → 重建网页 → 记录时间"全包了：

```bash
finradar update
```

**第一次运行**：从十年前开始，把政策文件库按年回捞一遍 + 抓全部实时源，
再重算打分、重建网页。约 3–5 分钟（实测首次入库 5,000+ 条）。

**之后的每一次**：只抓"上次运行日的前一天到现在"的新增。实测第二次运行
（隔一分钟）只新增 1 条、40 秒跑完。

它记在哪里：`output/state.json`，长这样——

```json
{
  "last_run": "2026-09-14T04:13:31+08:00",
  "last_mode": "增量",
  "last_new_items": 1,
  "last_span": "2026-09-13 ~ 2026-09-14",
  "runs": 2,
  "history": [ { "at": "...", "mode": "首次全量", "new": 5051, "span": "2016-09-14 ~ 2026-09-14" } ]
}
```

可以直接打开看，也可以**删掉它来重置**——下次 `finradar update` 会重新补十年。

常用开关：

| 开关 | 作用 |
|---|---|
| `--full` | 强制全量（忽略上次运行时间，重新补齐十年） |
| `--years 5` | 首次运行时往回补几年（默认 10） |
| `--start 2024-01-01` | 手动指定回捞起点 |
| `--no-backfill` | 只抓实时源，不动历史 |
| `--no-site` | 不重建网页（只要数据） |
| `--quiet` | 不逐源打印 |
| `--source trends` | 只抓指定的源（默认全部实时源） |

它每次做的事，按顺序：

```
① 政策文件库回捞   首次：十年前 → 今天（按年分段）；之后：上次运行前一天 → 今天
② 抓取实时源       官方站 / 快讯 / 证券时报 / 大众热榜 / AkShare（19 个）
③ 重算打分         改过 keywords.yaml 也能靠这一步自动生效
④ 重建网页         output/insights.html（专题 + 名词档案 + 候选词）
⑤ 记录状态         output/state.json
```

**建议频率**：每天一次（哪怕只跑 `--no-backfill --no-site` 只看数据）。
如果一个月没跑，它会自动把这一整个月的政策文件补回来——因为增量起点是
"上次运行日"，不是"上次抓到的最新日期"。

## 1. 三个循环

### 先决定"看多久"：窗口预设

所有查看类命令都支持 `--window`，不用再心算天数：

| 窗口 | 含义 | 默认粒度（自动） |
|---|---|---|
| `3m` | 近 3 个月 | 月 |
| `6m` | 近半年 | 月 |
| `1y` | 近 1 年 | 月 |
| `3y` | 近 3 年 | 季 |
| `5y` | 近 5 年 | 年 |
| `all` | 全部数据 | 年 |

粒度也可以手动指定：`--bucket month|quarter|year`。
**默认粒度是刻意偏粗的**——政策文件一周也就几条，按天或按周看全是 0 和 1，
看不出趋势。

### 每天 5 分钟：今天有什么政策

```bash
finradar crawl                                   # 默认 14 个源，约 1100 条，1~2 分钟
finradar report --days 3 --min-score 55          # 生成日报（Markdown + HTML）
```

产出：

| 文件 | 用途 |
|---|---|
| `output/reports/report_<日期>.md` | 直接看，或粘到笔记里 |
| `output/reports/report_<日期>.html` | 双击用浏览器打开，手机上也能看 |

日报结构：热词榜 → 按议题分组（货币政策 / 资本市场 / 银行保险 / 对外开放 / 主题热词 /
政策动作）→ 每条带**政策分**、**命中热词**、**传导逻辑**。只精读 ≥55 分的，其余扫标题。

几个约定：

- 同一 URL 只入库一次，天天跑不会把库撑爆；同一份文件被多个源转载会自动合并，
  并标注"同源报道"。
- 日期按**北京时间**算（`近 N 天` 也是）。
- `crawl` 不加参数 = 官方站 + 快讯 + 配置化政务站；`--source all` 再加上 AkShare 聚合快讯
  （那一路 600 多条，和直连源大量重复，按需开）。

### 每周 30 分钟：维护词库（这个项目的核心价值）

```bash
finradar hot --days 7 --trend --discover
```

- `--trend`：这一周哪些热词在涨（`--bucket day|week|month` 换桶）
- `--discover`：新词发现，捞出"最近反复出现、词库里还没有"的提法

**`--discover` 是提词器，不是词典**：它用字符 n-gram 统计，没有分词器，输出里会混进
人名、机构名、短语碎片。人工挑出真有价值的政策提法，照
[GLOSSARY_SCHEMA.md](GLOSSARY_SCHEMA.md) 的格式补一条（也见
`finradar/data/glossary/01_macro_monetary.yaml` 里现有词条）：

```yaml
- id: macro-xxx
  term: 新提法
  category: 宏观与货币政策
  heat: 4                # 1-5，5 = 2026 秋招几乎必问
  institutions: [券商, 公募, 银行]
  source: 出处（哪份文件、哪次会议）
  definition: 是什么
  why_hot: 为什么现在热
  exam_points: [考点1, 考点2]
  interview_answer: 60-90 秒口语化答法（写成能直接说出口的话）
  followups: [{q: 追问, a: 应答}]
  related: [关联词]
```

词库是即时生效的，不用重抓、也不用重启什么。

### 面试前一晚：只看一页 + 刷题

```bash
finradar report --days 7 --min-score 60         # 一周要闻
finradar terms --institution 券商 --heat 5      # 投券商前把五星词过一遍
finradar quiz -n 10                             # 交互刷题：回车跳过，q 退出
finradar quiz --wrong                           # 只刷错题本
finradar show -n 3 --board 固定收益与债券市场      # 不交互，直接看题和答案
finradar facts --keys lpr money_supply cpi      # 刷新一遍最新数据
```

刷题记录写进 SQLite，答错的自动进错题本，所以 `--wrong` 刷的是你真正没掌握的。

## 1.5 看长周期：3 个月 / 半年 / 1 年 / 3 年 / 5 年

短窗口看"今天发生了什么"，长窗口看"这几年金融政策在往哪走"。长窗口分两步：
**先把历史捞回来（一次性），再按窗口看。**

### 第一步：回捞历史（只用做一次，之后每月补一次）

```bash
finradar backfill --from 2021-01-01                 # 回捞政策文件库 2021 年至今
finradar backfill --from 2021-01-01 --max-pages 6   # 每年每个关键词多翻几页，覆盖更全
finradar backfill --source safe stats ndrc amac --pages 30   # 列表型源往深里翻页
```

能回捞什么，要诚实说清楚：

| 数据 | 历史能到多久 | 原因 |
|---|---|---|
| 中国政府网政策文件库 | **2011 年至今**，按日精确检索 | 接口支持 `mintime/maxtime`，可按年/季/月切成段 |
| 外汇局 / 统计局 / 发改委 / 基金业协会 | 列表页能翻多少页就到多久（外汇局约 145 页） | 只能靠 `index_N.html` 往前翻 |
| 央行 | 只有当前列表页 | 它的列表页没有可用的翻页地址 |
| 快讯（财联社/新浪/东财） | **只有当天** | 这类接口不提供历史 |
| AkShare 财经早餐 | 约 1.5 年（2025-01 起，每月 20 篇左右） | 是每日新闻摘要，能当"历史快讯"的替身 |

所以 **3 年以上窗口的"热点词汇演变"本质上是以政策文件为语料的**，
推出来的词是"政策提法"而不是"市场情绪词"。这恰好是面试要考的那一类。

### 第二步：按窗口看

```bash
# 热点词汇怎么演变（词 × 时段矩阵）
finradar hot --window 5y --trend --top 12
finradar hot --window 1y --trend --bucket month

# 回顾报告：热词榜 + 演变矩阵 + 分时段头条（Markdown + HTML）
finradar report --window 5y --min-score 78 --per-period 3
finradar report --window 6m --min-score 70
finradar report --window 3m                  # 3 个月以内仍按议题梳理, 不按时段
```

长窗口的报告会自动换成"回顾"形态：**热词榜 → 词 × 时段演变矩阵 → 分年/季/月回顾
（每段列出该时段的热点词汇和头条）**，并标注数据实际覆盖区间
（比如"近 5 年"里到底有几年数据）。

演变矩阵怎么读：

```
词                                2021  2022  2023  2024  2025  2026
“一行一局一会”新监管架构            ·     ·     50    78    66    34
适度宽松的货币政策                  ·     ·     ·     3     30    15
```

- 从 `·` 变成数字 = 这个词**出现了**（如"适度宽松的货币政策"2024 年底中央经济工作会议后出现）
- 数字爬升 = 提法在**升温**；数字掉下来 = 被新提法替代或政策落地完成
- 面试里"这几年金融政策有什么变化"的骨架，就是这张表的几行

```bash
# 日报（短窗口）和回顾（长窗口）用的是同一套命令, 只是窗口不同
finradar report --days 3 --min-score 55     # 日报
finradar report --window 5y                 # 回顾
```

## 1.6 专题洞察：不要只看文章，要看脉络和各方动作

抓到的新闻是"点"，看政策需要的是"线"：这条线怎么走到今天、现在卡在哪、
各方接下来可能做什么。专题洞察就是干这个的——目前 6 条主线：

| 专题 | 一句话核心判断 |
|---|---|
| 跨境投资开放（QDII / QFII / 互联互通） | 思路是"宽进慎出"：流入端已基本便利化，流出端仍按机构核准额度；看点在**节奏和通道**，不在放不放开 |
| 货币政策框架（稳健 → 适度宽松） | 数量工具天天用、价格工具慢慢来；判断力度要看公开市场操作的期限结构，不是只看降不降息 |
| 中长期资金入市 | 核心矛盾是"长钱短考"，所以政策一头放开比例、一头改考核 |
| 公募基金改革 | 费率三连降打断"规模即收入"，三条出路：被动化、多资产、买方投顾 |
| 银行：息差、资本、风险 | 三个约束同时挤压，应对是调结构而不是扩表 |
| 科技金融（科创债 / AIC / 耐心资本） | 关键不是授信额度，而是"风险由谁承担、退出通道通不通" |

```bash
finradar insights                    # 列出全部专题 + 核心判断
finradar insights --actor 公募        # 只看和公募相关的线
finradar insight QDII                # 一条线的完整洞察（关键词/id/专题名都能查）
finradar insight 息差 --window 3y     # 自动脉络只看近三年
finradar report --window 1y --insights   # 报告末尾附上相关专题（按窗口内热词自动挑）
```

`finradar insight` 输出六块：

1. **核心判断** —— 面试里先说的那一句
2. **脉络（人工整理）** —— 关键时间点 + 出处
3. **脉络（自动聚合）** —— 从你库里真实抓到的文件按年聚合出来的，带文号和链接
4. **现状快照** —— 数字都带截止时点
5. **未来可能的动作** —— 按主体拆：**监管 / 公募 / 券商 / 银行 / 保险 / 外资机构** 各自可能做什么，
   每条都写成「触发条件 → 动作」，比如：

   ```
   ▸ 公募（每轮额度下发后）
       可能动作：拿到新增额度先补欠配：恢复限购产品申购、分配到跨境 ETF 与港股主题
       触发条件：场内 QDII 溢价率持续高企（说明额度紧张），新额度到账就会先平抑溢价
   ```

6. **盯这几个信号** —— 具体到哪份表、什么频率（比如"外汇局《QDII 投资额度审批情况表》按月公示"）

想加自己的专题（比如固收、养老金融、区域金融），照
[GLOSSARY_SCHEMA.md](GLOSSARY_SCHEMA.md) 里的模板写一条 YAML 放进
`finradar/data/insights/`，`pytest -q` 会校验字段完整性、以及"关联热词必须真实存在"。

## 1.7 网页版：一个文件，手机也能翻

命令行适合自己看，给别人看（或者手机上翻）用网页：

```bash
python scripts/build_insight_site.py          # → output/insights.html
finradar insight QDII --html                  # → output/insights/crossborder-qdii-qfii.html
```

`output/insights.html` 是**单文件网页**（无依赖、离线可用），三个标签页：

| 标签页 | 里面有什么 | 数量 |
|---|---|---|
| **专题洞察** | 核心判断 / 脉络（人工 + 自动）/ 现状快照 / 各主体可能的动作 / 观察信号 / 面试口径 | 6 条主线 |
| **名词档案** | 每个热词的定义、考点清单、口语答法、追问应答，**外加语料里出现多少次、首见哪一年、逐年走势、代表文件** | 全部 46 个词条 |
| **候选新词** | 从过去几年的政策文件标题里自动挖出来的提法（词库还没有），带次数、首见年份、年度走势和例句 | 40 个候选 |

页面支持搜索（专题搜判断与关键词、名词搜定义与考点、候选词搜词），
专题还能按主体筛（只看公募 / 只看银行），名词能筛分类、或"只看语料里出现过的"。
样式与 `output/kb.html`（词库刷题页）共用一套，支持深色模式。

**名词档案是自动生成的**：不需要为 46 个词条各写一份文档，脚本会把词库内容和
你抓到的语料拼起来——定义来自词库，出现次数/首见年份/代表文件来自语料。
所以语料越全（跑过 `backfill`），档案越有说服力。

### 候选新词怎么用

这 40 个词是**从政策文件标题里挖出来的**（字符 n-gram + 后缀定向抽取
「…机制/体系/试点/额度/账户/平台」+ 碎片剔除 + 过滤机构名和公文常用语），
它是"待人工确认的候选池"，不是权威口径。用法：

1. 看年度走势——**近三年才出现的**最值得做词条（老词早就该会了）
2. 点开例句看语境，确认它是不是一个真提法（不是跨词碎片）
3. 有价值就照 [GLOSSARY_SCHEMA.md](GLOSSARY_SCHEMA.md) 补成词条或专题，
   然后 `pytest -q` 会把字段完整性校验一遍

对应的命令行版本：

```bash
finradar hot --window 3y --discover --top 30    # 同一套算法的即时版
```

## 1.8 专题报道：成篇的文章，不是条目

洞察速查（`finradar insight`）是条目式的，适合扫；**专题报道**是成篇的，适合通读、也适合
面试前把一段逻辑讲顺。每篇的结构是：

```
导语（一句话点破这件事的关键）
  ↓
数据支撑（自动生成：这条线在库里有多少文件、最早哪年、近三年占比、最近一份正式文件）
  ↓
这条线是怎么来的 → 今天站在哪 → 各方接下来可能怎么做 → 反方观点与风险 → 面试里怎么说
```

```bash
finradar features                      # 列出 6 篇报道的标题与导语
finradar feature QDII                  # 读一篇（Markdown，直接贴在终端/笔记里）
finradar feature 货币政策 --out 货政.md  # 值得留存就写到文件
finradar features --out output/features.md   # 6 篇合并导出成一个 md
finradar feature QDII --html           # 导出成网页（含关联名词档案）
```

网页版（`output/insights.html`）的第一个标签页就是「专题报道」，页面顶部有目录，
点一下跳到那篇；还支持在正文里搜索。

**报道正文是人工写的，数据是自动的**：正文写在 `finradar/data/insights/*.yaml` 的
`feature` 字段里（导语 + 若干段落），渲染时脚本会织入一段「数据支撑」和一份
「主要文件（供核对）」，所以旧文也不会因为数据过期而失真——
每次重新生成，数字都是当下库里的真实统计。

写报道的三条经验（和写条目不一样）：

1. **导语要给判断，不要给背景**。"关于跨境投资最容易搞混的是开放开了哪一头"比
   "近年来我国稳步推进金融开放"有用得多。
2. **段落之间要有转折**。有"各方接下来可能怎么做"，就一定要有"反方观点与风险"，
   否则读起来像宣传材料。
3. **数据和判断分开**。判断写在正文里，数字留给自动生成的「数据支撑」段，
   这样数据过期时你只需要重新生成，不用改文章。

## 1.9 扩量：从 40 个候选到 150+，以及抖音/头条热榜

词表偏少的根因是**语料不够大**，不是过滤太严。两条扩量路径：

### ① 把语料做大

```bash
finradar backfill --from 2021-01-01        # 政策文件按日期范围回捞（一次性）
finradar crawl --source all --pages 2      # 全量抓：含新加的 证券时报、以及三个大众热榜
```

新接入的源：

| 源 | 通道 | 作用 |
|---|---|---|
| 证券时报 `stcn.com` | 实时快讯（只有 HH:MM，按当天处理） | 补上"市场层面"的新闻，政策文件里看不到 |
| 今日头条热榜 | JSON 接口 | 大众关注度 |
| 抖音热榜 | JSON 接口 | 大众关注度（最能反映"出圈"话题） |
| 百度热搜 | JSON 接口 | 大众关注度 |

> 微博热搜（403）和知乎热榜（401）实测拿不到，没接。交易所规则页是 JS 渲染，也没接。

### ② 大规模挖掘

```bash
finradar mine --top 200                              # 列出候选提法（带次数、首见年份、近三年走势）
finradar mine --top 200 --trends                     # 同时列出热榜里的财经话题
finradar mine --top 200 --out output/drafts/terms_draft.yaml   # 导出词条草稿
```

实测：7,900 条语料 → **153 个候选提法**（此前 6,945 条语料只有 40 个）。
排序按"**近三年出现占比**"，所以排在前面的是这两三年才高频起来的提法，
而不是"金融市场""税收政策"这类一直在讲的老词。

草稿文件里每个候选都带了 `TODO 待补`，挑出有价值的补完 `definition / why_hot /
exam_points / interview_answer`，再挪进 `finradar/data/glossary/` 就是正式词条。

### ③ 看热榜里的财经话题

```bash
finradar crawl --source trends      # 抓三个热榜（约 150 条）
finradar trends                     # 只列财经相关的话题，跨平台合并去重
finradar trends --all               # 连娱乐体育一起看（按平台列出）
```

150 条热榜里通常只有 8–15 条与金融相关，脚本用金融/宏观词表筛出来并按热度排序。
**一个话题同时出现在三个榜上**，说明它真的出圈了——这类词是面试里"你最近关注什么"
的标准答案素材。

热榜噪音大，所以：**默认不参与日报和政策热词统计**（`source=*_hot` 被排除），
要用 `--include-trends` 显式打开。

## 1.10 十年视角：从 2015 年看今天

政策和词条都能往前推十年——前提是**语料先回捞到十年前**。

```bash
finradar backfill --from 2015-01-01 --to 2020-12-31    # 补齐 2015–2020（一次性）
finradar hot --window 10y --trend --top 14             # 词 × 年 演变矩阵（2016→今天）
finradar report --window 10y --min-score 70            # 十年回顾报告
finradar mine --top 200                                # 在十年语料上挖候选词
```

政策文件库实测可回溯到 2013 年：2020 年 979 条、2017 年 366 条、2015 年 375 条
（"金融"全文命中数），补齐后库内约 1.1 万条、最早到 2000 年。

**十年矩阵的价值是看"起落"**：哪些词是老词（一直在讲），哪些是新词（近三年才起来），
哪些讲着讲着就没了。举几个实测结果：

| 词 | 首见 | 峰值 | 说明 |
|---|---|---|---|
| 金融"五篇大文章" | 2016（含五个领域词） | 2025 | 五个领域早就有，2023 年才被归为"五篇大文章" |
| "一行一局一会"新监管架构 | 2023 | 2024 | 机构改革当年冲高，之后常态化 |
| 适度宽松的货币政策 | 2024 | 2025 | 2024 年底基调转向后才出现 |
| 人工智能+金融 | 2025 | 2025 | 最新的提法 |

选词条的判断标准也变了：**优先"近三年才高频出现"的**（老词早就该会了）。
`finradar mine` 已经按近三年占比排序，年度走势直接列在候选后面。

> 注意：热榜（头条/抖音/百度）**没有历史**，只能看当天；十年视角靠的是政策文件库。
> 所以十年维度的"热词"本质是**政策提法**的演变，不是大众关注度。

## 1.11 四重视角：官方 / 媒体 / 海外 / 专题

这个工具的核心不是"抓到一条新闻"，而是**把同一条政策的多重视角放在一起**：

```
① 官方原文   政策文件库、部委、央行（带文号）
② 权威媒体   新华社、三大证券报、证券时报、中国政府网要闻
③ 海外解读   Google News 聚合（路透/彭博/南华早报…）、美联储、世界银行、Rhodium Group
④ 专题分析   脉络 / 现状 / 各主体可能的动作 / 外部视角
```

报告会自动带上 ②③ 两节：

```bash
finradar crawl --source media external   # 只抓媒体与外部视角
finradar report --days 5 --min-score 65  # 报告里出现「媒体视角」「外部视角」
finradar insight QDII                    # 专题里的「外部视角」块
finradar feature QDII                    # 专题报道末尾附外部视角
```

实现上的三个注意点：

- **媒体与外部视角不套 `--min-score`**：它们本来不是政策文件，政策分天然低，
  所以报告单独取一遍数据（`view_rows`），只按"是否命中本期热词"筛。
- **海外报道是英文的**，所以内置中英词表（`analysis/views.py` 的 `CN2EN`）：
  "货币政策 → monetary policy"、"人民币 → yuan / renminbi"、
  "化债 → debt swap / hidden debt"、"房地产 → property / real estate"。
  没有这层映射，中文热词永远匹配不上英文标题。
- 命中不到时不硬凑：外部视角退回"近期海外动态"，并明确标注**未与本期热词对应**。

新增的源（2026-09-14 实测）：

| 源 | 通道 | 说明 |
|---|---|---|
| 新华社·财经 / ·金融 | HTML | 国家通讯社的经济金融报道 |
| 中国证券报 / 上海证券报 / 证券日报 / 证券时报 | HTML | 三大证券报 + 证券时报 |
| 中国政府网·要闻 | 静态 JSON（400 条） | 政府直接的新闻出口；列表页 JS 渲染，直接抓 JSON 更稳 |
| Google News | RSS | 10 组检索词（货币政策/资本市场/互联互通/债市/地产/地方债/人民币/险资/绿色/科技金融） |
| 美联储 / 世界银行 / Rhodium Group | RSS / API | 海外官方与专业研究机构视角 |

> 拿不到的：微博热搜 403、知乎热榜 401、国新办网站 521、IMF 403、BIS 与世界银行 RSS 404
> （世界银行改走它的搜索 API）。这些写清楚，不假装能抓。

## 3. 想改东西时改哪里

| 想改什么 | 改哪个文件 | 改完做什么 |
|---|---|---|
| 打分松紧、加新关键词 | `config/keywords.yaml` | `finradar rescore` |
| 加一个政务数据源 | `config/sources.yaml` | `finradar doctor` 验证 |
| 补热词 / 考点 / 答法 | `finradar/data/glossary/*.yaml` | 即时生效 |
| 补题 | `finradar/data/questions/*.yaml` | `pytest -q` 会校验字段完整性 |
| 改抓取逻辑 | `finradar/crawlers/*.py` | `pytest -q && ruff check .` |

`config/sources.yaml` 加站点的关键是 `require_date: true`——导航菜单也是 `li`，
没有日期的条目会被自动丢掉。其他可用字段（`container_selector` / `page_pattern` /
`min_title_len`）文件开头都有注释。

## 4. 排障

```bash
finradar doctor                  # 先体检：哪个源挂了
finradar -v crawl --source cls   # -v 打开调试日志
finradar crawl --source pbc --no-save    # 单源试跑，不写库
```

| 现象 | 处理 |
|---|---|
| 某个政务站抓不到 | 大概率是接口改版或 WAF，先 `finradar doctor` 看是哪个，再降低频率重试 |
| 报 TLS / 证书错误 | 加 `--insecure` |
| 单个源特别慢 | 对方站点响应慢（内置重试），重跑一次；只关心官方源就 `--source official` |
| 日报条目太多 | 提高 `--min-score`（55 → 65），或缩短 `--days` |
| 日报条目太少 | 降低 `--min-score`，或先跑一次 `finradar crawl` |
| 分数看着不对 | 改的是 `keywords.yaml` 就 `finradar rescore`；有疑问用 `--no-save` 单源试跑看命中词 |
| 改了代码想验证 | `cd ~/Downloads/china-fin-radar && pytest -q && ruff check .` |
