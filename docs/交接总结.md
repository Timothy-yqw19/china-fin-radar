## 0. 三十秒了解

**是什么**：一个金融政策解析工具。把同一条政策的四重视角放在一起——
官方原文 → 权威媒体 → 海外解读 → 专题分析，再附一套秋招金融知识库（热词/题库/刷题）。

**仓库**：https://github.com/Timothy-yqw19/china-fin-radar（main 分支，28 次提交）

**网站**（GitHub Pages，已上线）：

## 1. 日常就一条命令

```bash
cd ~/Downloads/china-fin-radar
finradar update --publish --push
```

它一次做完：

```
① 政策文件库回捞   首次：十年前→今天（按年分段）；之后：上次运行前一天→今天
② 抓取全部实时源   官方站 / 权威媒体 / 大众热榜 / 海外视角 / 快讯 / AkShare（29 个）
③ 重算打分         改过 config/keywords.yaml 也会自动生效
④ 重建网页         output/insights.html（专题 + 名词档案 + 候选词）
④.5 归档通报       生成公文版 → docs/reports/（保留最近 30 期）→ 刷新索引
⑤ 提交推送         git add/commit/push → 网站约 1 分钟后更新
⑥ 记录状态         output/state.json
```

常用变体：

| 场景 | 命令 |
|---|---|
| 只更新数据，不发网站 | `finradar update` |
| 只写网站文件，先检查再决定发布 | `finradar update --publish` |
| 快刷，不重建网页 | `finradar update --no-site` |
| 只抓实时源，不动历史 | `finradar update --no-backfill` |
| 换源/重来，重新补十年 | `finradar update --full` |
| 只看报告 | `finradar report --days 3 --min-score 55` |
| 看公文版/口语版 | 默认公文；加 `--style plain` 切口语版 |

**最近一次运行**：2026-09-14（`output/state.json`）。当前是 2026-10-24，
下次 `finradar update` 会自动把 9/13 至 10/24 这一个多月的政策文件补回来。

```

  政策原文  ───────▶ │ crawlers/（29 个源）          │
  权威媒体  ───────▶ │  official / feeds / trends / │
  大众热榜  ───────▶ │  flash / ak_source / config   │
  海外视角  ───────▶ └──────────────┬───────────────┘
                                    ▼
                        analysis/tagger（打分+标签+传导路径）
                                    ▼
                     SQLite（去重、时间窗口、跨源合并）
                                    ▼
        ┌───────────────────────────┼───────────────────────────┐
        ▼                           ▼                           ▼
  分析/报告                    知识库/专题                    网站/发布
```

## 4. 关键设计决策（改动前先读）

1. **来源先验分只做下限（≤30）**：官方站不能天然 70–80 分，否则央行的例行会见也能 100 分。
   现在 90 分以上只留给"发文动作 + 官方主体 + 具体领域"的真政策。
2. **例行事项不吃协同加分**：会见/座谈/培训班命中 routine 类目时，不加"主体+领域"的协同分。
3. **跨源去重**：按"去掉《关于…的通知》等包装词后的标题 + 同文号"合并；
   不做模糊相似度合并（会把"第178号/第177号"这类公告误合并）。
4. **时间统一按北京时间**（`utils.CN_TZ`）；否则在美东跑"近 N 天"会差一天。
5. **媒体/外部视角不套 `--min-score`**：它们不是政策文件，分数天然低。
   报告里单独取一遍数据（`view_rows`），只按"是否命中本期热词"筛。
6. **中英词表**（`analysis/views.py` 的 `CN2EN`）：中文热词要映射成英文说法
   （货币政策→monetary policy、人民币→yuan…），否则匹配不上英文报道。
7. **时间窗口与粒度分开**：窗口 3m/6m/1y/3y/5y，粒度自动变粗
   （≤45 天按周、≤400 天按月、≤3 年按季、更长按年）。
8. **新词挖掘**：只在**标题**上挖 + 政策名词后缀定向（…机制/试点/额度/账户/平台）
   + 全量 n-gram 碎片支配判断 + 机构名/公文体裁/动词首尾过滤；按"近三年占比"排序。
9. **增量靠 `output/state.json`**：记 `last_run`，下次从"上次运行日前一天"开始
   （重叠一天，靠 uid 去重）。删掉该文件 = 重置为首次全量。
10. **文风双档**：`--style formal`（默认，公文/申论体）与 `--style plain`（口语速览）。
11. **翻译有缓存与预算**：`output/translate_cache.json`；mymemory 匿名额度约 5000 字符/天，
    内置 4000 字符预算，超限跳过。
12. **ruff 显式规则集**（`pyproject.toml`）：不写死规则集，CI 会因 ruff 版本漂移突然报错
    （踩过：本地 0.12 通过、CI 0.16 报 93 条）。且**不能启用 RUF001-003**，
    它们会把中文全角标点全判成错误（700+ 条噪音）。

## 6. 网站与发布

**工作流**：`.github/workflows/pages.yml` —— 推送 main 触发，
`scripts/build_static_site.py` 构建 `public/`（只用仓库 YAML，不需要本地库），再发布 Pages。

**发布什么**：

```
public/index.html          专题报道 + 洞察速查 + 名词档案（静态版）
public/kb.html             刷题页
public/docs/reports/       公文版通报归档（finradar publish 生成）
public/docs/*.md           使用说明、项目总结、手册、银行面试专题
public/docs/*.html         长文排版页面（.md 自动渲染，面试专题用这个）
```

**静态版与本地完整版的差异**：

- 静态版**没有**「数据支撑」段与「候选新词」（需要本地 12,000+ 条语料库）
- 页面顶部会显示一行说明，避免读者误以为出错
- 本地完整版：`finradar update` 后打开 `output/insights.html`

**归档命令**：

```bash
finradar publish                 # 生成 + 归档 + 刷新索引（不推送）
finradar publish --push          # 再自动提交推送
finradar update --publish --push # 日常一条命令（推荐）
```

归档只留最近 30 期（`--keep` 可调），避免仓库膨胀。

## 7. 已知限制（接手前必读）

1. **交易所未接入**：上交所规则页 JS 渲染；`query.sse.com.cn` 需要正确的 `sqlId`。
   深交所 API 有 TLS 重置。这是最大的数据缺口（上市/交易规则词）。
2. **热榜没有历史**：抖音/头条/百度只给当前榜；十年视角只能靠政策文件库。
3. **国新办/微博/知乎/IMF 挡爬**：已在文档写明，不要重复试。
4. **只有标题+摘要**：没有抓正文，打分基于标题/摘要/栏目。
5. **候选新词仍有约 20% 噪音**：机构名碎片、跨词片段；需要人工确认后补进词库。
6. **mymemory 翻译质量一般**：`--translate codex` 质量更好但需本机 codex CLI 可用。
7. **静态站点无数据支撑**：要完整版必须本地跑。
8. **词库/题库/专题仍是手工 YAML**：`--discover`/`finradar mine` 只出候选，不自动写词条。
9. **无增量时间游标以外的断点续抓**：单源失败会跳过，下次重跑会补。
10. **默认不抓热榜进统计**：热榜被排除在打分/热词之外（`--include-trends` 可打开）。
