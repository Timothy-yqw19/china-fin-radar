## 二、项目在做什么

一句话：**把同一条政策的四重视角拼在一起 —— 官方原文 / 权威媒体 / 海外解读 / 专题分析**，
再顺手接上秋招考点（热词、题库、刷题）。

```
官方政策站点 ─┐
财经快讯     ─┼─▶ 政策相关度打分 ─▶ 热词榜 ─▶ 日报(MD/HTML)
AkShare      ─┘                      │
                                      └─▶ 热词库(考点+答法) ─▶ 刷题/错题本
```

### 代码规模

- Python 约 **4,000 行**（19 个数据源 + 打分 + 报告 + 时间窗口 + 知识库 + CLI）
- 数据 YAML 约 **5,400 行**（52 个词条 + 62 道题 + 8 条专题洞察）
- 测试 **200 个，全部通过**；`ruff` 无告警

### 三大模块

**1. 抓取（`finradar/crawlers/`）—— 30+ 个数据源，全部在真实网络验证过**

| 类型 | 数据源 | 通道 |
|---|---|---|
| 官方政策 | 中国政府网政策文件库、证监会、金融监管总局 | JSON 接口 |
| 官方政策 | 中国人民银行（含公开市场业务交易公告）、国家外汇管理局 | HTML |
| 官方政策（配置化） | 财政部、发改委、国家统计局、基金业协会 | `config/sources.yaml`，不用写代码 |
| 快讯 | 东方财富 7×24、财经早餐、财联社电报、同花顺、新浪 | JSON 接口 |
| 兜底+宏观 | AkShare | Python 包 |

**2. 分析（`finradar/analysis/`）**

政策相关度打分（0–100），规则写在 `config/keywords.yaml`：

- 六类关键词各自加权（政策动作 / 发文主体 / 货币 / 资本市场 / 银行保险 / 对外开放 / 主题）
- 同类多次命中**递减计分**，单类封顶 2 倍权重
- **协同加分**：只有"官方主体 + 具体领域"同时命中才算真政策新闻
- **噪音降权**（涨停、龙虎榜、概念股、午评）+ **例行事项降权**（会见、座谈、调研）
- 附一句**传导逻辑**，例如：化债 → 高息城投换低息政府债 → 银行资产质量改善但收益率下降 → 加剧"资产荒"

**来源先验分只做下限（0–30），不参与排序。** 这是这一轮最重要的口径修正：
早期版本给官方站 70–80 分，结果央行领导一场例行会见也能顶到 100 分，日报完全没有区分度。
现在分数由关键词信号决定——全库 1552 条里只有 **28 条** 到 90 分以上
（修改前是 791 条），例行会见与培训班这类事项落在 45–70 分。

**3. 知识库（`finradar/data/`）**

**46 个热词**，六大分类（25 个标为 ★★★★★）：宏观与货币政策 10、资本市场与证券行业 10、
对外开放与跨境投融资 7、银行与保险 7、金融风险与监管体系 7、科技金融与数字金融 5。

每条的字段：定义 → 出处 → 为什么热 → **考点清单** → **60–90 秒口语化答法** →
数据快照（带 as-of）→ **追问及应答** → 关联词。

**62 道题**（这一轮从 51 补到 62），六大板块：宏观 12 / 固收 11 / 权益 10 / 公募 10 / 银行 9 / 监管与职业素养 10。
题型含单选、多选、简答、情景题，每题都有考点、标准答案、口语化表达、追问延伸。

## 三、达到了什么

**1. 联网抓取在真实网络下全部跑通（这一轮的核心里程碑）**

上一轮所有境内站点都超时，无法验证。这一轮在真实网络下逐个跑通并**修掉了 4 个静默失败**：

- **政府网政策库**：接口把结果挪进了 `searchVO.catMap`，旧代码读顶层 `catMap`，
  **抓到 0 条却不报错**；现在兼容两种结构并支持翻页（439 条）。
- **央行**：过滤条件写的是"跳过含 index 的链接"，而央行的详情页 URL 全是
  `/…/index.html`——等于把每一条正文链接都扔了；改用 `a[istitle="true"]` +
  `span.hui12` 取日期（82 条），并补上"利率政策""公开市场业务交易公告"两个栏目
  （面试问"今天央行做了什么"，答案就在这个公告里）。
- **外汇局**：`/safe/xwfb/` 已改名，404 被静默吞掉；改为政策法规 / 外汇新闻 / 要闻发布 + 翻页。
- **`config/sources.yaml` 一直是死配置**：`ConfigListCrawler` 从没被任何地方实例化，
  README 宣称的"零代码扩展"其实没生效。现在接进 `build_all`，并按真实页面重写
  财政部 / 发改委 / 统计局 / 基金业协会四个源（新增 `require_date`、`container_selector`、
  `page_pattern` 三个能力，`require_date` 能自动滤掉导航菜单）。

一轮全量抓取约 **1700 条**，`finradar doctor` 15 个源全部 ✓。

**2. 修掉了打分链路上几个会误导判断的问题**

- 例行会见/座谈不再和正式发文同分（见上文口径修正）。
- **跨源重复**：同一份文件被政府网、财政部、财联社同时抓到，日报会显示三遍。
  现在按"标题去包装词后比对 + 同文号"合并，并标注"同源报道"。
- **宏观数据取成了 2008 年的**：akshare 各接口排序方向不一致（M2/CPI 是"新→旧"，
  LPR/中美国债是"旧→新"），代码无脑用了 `tail()`；现在统一按时间列重排取最新。
  另外 `interbank_rate_em` 在当前 akshare 版本里已不存在，换成 `rate_interbank`，
  并补上社融、新增信贷、中债收益率曲线，共 12 项。
- **时区**：境内站点按北京时间发布，日期统一按 UTC+8 解释；否则在美东跑，
  "近 N 天"的口径会凭空差一天（实测快讯里出现过"明天"的日期）。

**3. 新增两个实用能力**

- `finradar rescore`：改完 `keywords.yaml` 不用重抓，直接把库里已有条目重算一遍
  （这一轮就是靠它把 1552 条历史数据从"791 条 100 分"重算成正常分布）。
- 新词发现从"朴素 n-gram"改成**字符 n-gram + 文档频率 + 左右邻多样性 + 碎片剔除**，
  输出从一堆 `iPhone / 当地时间 / 日下午` 变成可用候选（计划单列市、降准降息、
  银行保险机构这类）。

**4. 题库补到 62 题**

重点补的是"能体现区分度"的题：公开市场工具箱（含"国债买卖≠QE"）、
给三个宏观数现场组织判断、银行间 vs 交易所市场、资产荒的成因与风险、
注销式回购 vs 股权激励回购、红利策略的四种失效条件、公募 REITs、
浮动费率基金的"锚"、手工补息整改的传导，以及两道合规情景题。

**5. 每个修过的 bug 都留了回归测试**

测试从 120 涨到 143：政府网 `searchVO` 结构、央行链接过滤、配置源是否真的进了
`build_all`、宏观数据是否取到最新一期、跨源合并、时区、新词发现的碎片过滤，
都各有一条测试守着。另有一组测试逐条校验词库题库的**字段完整性**。

**6. 长周期视角：从"看今天"变成"看演变"**（第三轮）

原来只有"最近 N 天"的口径，看 3 个月以上就全是空白（库里只有三周数据），
而且按天/按周统计太碎。这一轮补齐了整条链路：

- **回捞历史**：`finradar backfill` 走政策文件库的 `mintime/maxtime` 接口，
  按年月切成段、逐页往回捞（实测 2021—2026 每年 1000+ 份文件，入库 5398 条），
  列表型源（外汇局/统计局/发改委/基金业协会）则按页码深度回捞。
  快讯类接口没有历史，这点在文档里写清楚了。
- **窗口预设**：`--window 3m|6m|1y|3y|5y|all`，粒度自动跟着变（3 个月按月、
  1 年按季、5 年按年），不用再心算天数，也不会碎成一片 0 和 1。
- **演变矩阵**：`hot --trend` 输出"词 × 时段"表，并补齐中间没有数据的时段
  （否则时间线会跳月）；中文按双宽对齐。
- **回顾报告**：报告在长窗口下自动换成"热词榜 → 演变矩阵 → 分年/季/月回顾"，
  并标注数据实际覆盖区间。

顺带修掉两个统计口径问题：`回购` 会匹配到"逆回购/债券回购"导致重复计数和
张冠李戴的传导逻辑；"人民银行 / 中国人民银行"这类互为子串的关键词被记两遍。

**7. 专题洞察：从"抓到一篇文章"到"讲清一条线"**（第四轮）

原来日报里的东西是"一条条新闻 + 打分"，缺结构化判断。这一轮加了**专题洞察层**：
每条主线（目前 6 条）给六块内容——

- **核心判断**：面试里先说的那一句
- **脉络（人工整理）**：关键时间点 + 出处（如 QFII 2002 年设立、2019-09-10 取消额度）
- **脉络（自动聚合）**：按 `keywords` 把库里真实抓到的文件按年聚合，带文号与链接
- **现状快照**：数字全部带 as_of（如 QDII 累计额度 1761.69 亿美元 @2026-06-30）
- **未来可能的动作**：**按主体拆**（监管 / 公募 / 券商 / 银行 / 保险 / 外资机构），
  每条写成「触发条件 → 动作」，例如"公募：拿到新增额度先补欠配，
  触发条件是场内 QDII 溢价率持续高企"
- **盯这几个信号**：具体到哪份表、什么频率

`finradar insights` / `finradar insight QDII` / `finradar report --insights` 三个入口，
报告里的专题由窗口内热词自动匹配。测试会校验展望条目的主体与动作、脉络的时间与事件，
以及 **`related_terms` 必须真实存在于词库**（防止引用漂移——这条测试当场就抓出了
我写错的 5 个词名）。

**8. 专题报道：从条目到成篇**（第六轮）
+
+洞察速查是条目式的（脉络清单、按主体拆的动作），适合扫；但"讲给面试官听"需要成篇的语言。
+所以又加了一层**专题报道**：每条主线一篇，结构是「导语 → 数据支撑 → 这条线是怎么来的 →
+今天站在哪 → 各方接下来可能怎么做 → 反方观点与风险 → 面试里怎么说」，
+每篇正文 800–1200 字，**数据部分由脚本实时织入**（这条线在库里有多少文件、最早哪年出现、
+近三年占比、最近一份正式文件），所以文章不会因为数字过期而失真。
+
+反方观点段落是刻意要求的：只有"各方会怎么做"没有"风险与反例"，读起来就变成宣传材料。
+测试也把这条写进去了——正文合计不足 600 字（说明又写成了条目）、或没有分主体的动作描述，都会报错。
+
+顺带清掉一个隐患：demo 演示用的 10 条**假新闻**（链接是 example.invalid）
之前被塞进了真实语料，会让专题脉络和日报里出现不存在的新闻。
现已从库里清除，`demo_seed.py` 也改成默认写到 `output/demo/`，不再污染主库。

## 四、未达到什么

### ✅ 1. GitHub 已推送

`git@github.com:Timothy-yqw19/china-fin-radar.git`，main 分支已上去，
CI 配置（`.github/workflows/ci.yml`）会随 push 自动跑（pytest + ruff）。

唯一没做的是把仓库设成 private —— 这份库里有你的投递方向和面试准备笔记，
要不要公开由你决定（Settings → Change visibility 一键切换，历史提交都保留）。

### ⚠️ 2. 交易所（上交所 / 深交所）没有接入

它们的规则列表是 **JS 渲染**的：页面骨架里没有数据，`/lawandrules/` 抓下来
只有导航。要接得用 headless browser，或逆向它们的内网 JSON 接口（需要正确的
`sqlId`/`Referer`，我试了几个都不通）。目前 15 个源里没有交易所，
`config/sources.yaml` 里留了注释说明原因。

### ⚠️ 3. `--discover` 仍然是"提词器"不是词典

用的是字符 n-gram，没有分词器（环境里没有 jieba 等）。实测算下来，
候选里大约还有两三成是人名、机构名或短语碎片（比如"国人民银行副行长"）。
已经加了虚词过滤、左右邻多样性、碎片剔除三道，但**结果必须人工过一遍**才有用。

### ⚠️ 4. 题库 62 题仍然是"够用不够刷"

真实笔试一套就四五十题。现在的定位还是**考点索引**而不是题海。
补题最省力的路径：按你实际投的机构方向，重点补对应板块的 YAML，
字段完整性测试会自动校验不写漏。

### ⚠️ 5. 只有 2 个词条带完整数据快照

QDII、适度宽松货币政策有 `facts_snapshot`，其余靠 `finradar facts` 现拉。
数字类内容建议答题时都带 as_of，比记错数字安全。

### ⚠️ 6. 没有做的事

- 没有反爬对抗（代理池、验证码、浏览器渲染）——政务站 WAF 强化就抓不到
- 没有增量抓取的时间游标，每次是全量拉 + 去重
- 没有全文抓取，只抓标题和摘要（打分只基于标题 + 摘要 + 栏目）
- 词库更新还是手写 YAML，`--discover` 只能提示新词，不能自动生成词条
- 网页版的刷题进度依赖 Artifact 的 db 能力，不可用时会退回 localStorage（单设备）

### ⚠️ 7. 内容准确性有边界

- 政策解读是整理，不是权威口径，**以官方原文为准**。
- 数字都会过期：日报里的宏观数据请以 `finradar facts` 现拉的为准；
  题库里带 `as_of` 的数字（如 LPR 3.00/3.50，2026-08-20 报价）答题前值得核一遍。
- 涉及监管规则细节的题（如市值管理指引、科创成长层等），面试前对一遍官方原文。

## 五、建议的下一步

按性价比排序：

1. **确认 CI 是否全绿**（Actions 标签页），顺带决定仓库要不要保持公开。
2. **把这轮的真实数据跑成习惯**：`finradar crawl --source all` 之后
   `finradar report --days 3 --min-score 55`，只看那一页。
3. **每周 `finradar hot --days 7 --discover`**，把人工确认过的新提法补进词库——
   这才是这个项目相对于静态资料的真正价值。
4. **补题库**：按投递方向加题（投固收就重点补 `02_fixed_income.yaml`）。
5. **如果想让抓取更稳**：给政务站加一个可选的浏览器渲染通道（Playwright），
   顺手就能把交易所也接进来。
